# Frontend validation record

Worker-side evidence for the SCOOP site (web/ source, dist/ export). This is the worker's report,
not a network certification. The browser used here has no internet, so every live-chain
observation below comes from Node scripts run against the worker's Ethereum RPC relay, not from the
rendered page.

## 1. Scope and assumptions

- Pages: front page (`#/`), archive, single issue, book the front page, buy & sell. Build at
  `dist/`, generated by `web/` (Vite 7, React 19, wagmi 2, viem 2). Chain 1 (Ethereum) from the
  handoff; `network.json` present, so swaps are enabled.
- Issues live in `web/public/issues/` (export `dist/issues/`) because repository-root `issues/` is
  outside this assignment's write scope. `DESIGN.md` is at `docs/DESIGN.md` for the same reason.
- Issue #1 is built from on-chain data only. `https://imd.fun/api/...` returned the site's 404 page
  for the paths tried and no API documentation was supplied, so the API half of the brief is unmet
  and said so in the issue's standfirst. On-chain inputs (blocks 26,167,945–26,175,145): two
  IMD-paired v4 pools initialised (OFFSETS, SCOOP), 6 swaps / 15,480,115 SCOOP / 40.13 IMD on the
  SCOOP pool, slot0 tick −128586, liquidity 1,395,488,085,257,384,418,720,526, 564 IMD-paired pools
  ever. The swarm-wide quiet-pool scan hit the relay's 10 MiB response cap and was not completed.
- No WalletConnect project id was supplied: injected wallets only.

## 3. Browser inspection (export at `http://127.0.0.1:8899/dist/index.html`)

- Loads from the subpath with relative assets; title "SCOOP"; no JS exceptions. Console errors are
  only `ERR_INTERNET_DISCONNECTED` for the two public RPC URLs (browser has no internet) and, before
  the fix, a favicon 404 (fixed with an inline SVG icon).
- 320 × 900: front page, book page. Masthead, nav, wallet bar, sponsored box, issue sections,
  calendar (5 per row), form and footer reflow without horizontal overflow. Selected day shows red
  with white bold text; booked/unknown states read "Could not read bookings." when RPC is down.
- 1280 × 900: trade page, two-column layout, card on the right; quote/balance rows show "—",
  "reading…" then "unavailable" states without RPC.
- Interactions exercised: route changes via nav, day selection (`aria-pressed`), typing a headline
  (counter updates), typing a swap amount (quote state changes). Accessibility snapshots show
  landmarks (banner, navigation, main, contentinfo), labelled textboxes, named buttons, regions
  per section.
- Not performed: wallet connection, chain switch, approvals, booking, burn, veto, setPrice and swap
  in a real wallet (no wallet and no funds on this worker; no transaction was broadcast); screen
  reader session; native 200 % zoom; physical device; measured contrast (ratios below are computed
  from the hex tokens, not sampled from pixels): ink `#141211` on paper `#f6f1e7` ≈ 15.9:1, red
  `#b3261e` on paper ≈ 6.0:1, white on red ≈ 6.3:1, `--ink-3` `#6d6762` on paper ≈ 4.9:1.
- Screenshots could not be saved into the repository (the browser tool's save path is read-only);
  they were inspected inline and are described above, not shipped.

Findings and fixes:

1. LOW, `web/src/styles.css` `.day` — day tiles wrapped "13 Oct" onto two lines inconsistently at
   320 px (observed). Fix: `white-space: nowrap`. Rechecked in the rebuilt CSS (rendered recheck
   not repeated).
2. LOW, same — selected day was distinguished by colour alone visually. Fix: bold weight and an
   inset paper ring in addition to `aria-pressed`.
3. LOW, `web/index.html` — favicon 404 in the console. Fix: inline SVG `rel="icon"`.
4. Accepted as designed: the 627 kB JS bundle (wagmi/viem) is one chunk; well under the 8 MiB per
   file and total budgets, so no code splitting was added.

Complete for the stated scope, with these limitations: wallet-driven transactions were validated by
